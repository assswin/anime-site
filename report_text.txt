Fix 1: isActive Prop in HorizontalScroll.jsx
This is the most impactful single-line bug. Every CharacterCard rendered inside HorizontalScroll is missing its isActive prop, which means:
The text scramble effect never triggers
The "Tap to unleash" label never appears
Click to open VideoExpander is permanently broken
Hover glow, scale, and parallax physics are all disabled
Current broken code in HorizontalScroll.jsx:
  <CharacterCard
    character={character}
    index={index}
    onSelect={onSelectCharacter}
  />
Fixed code:
  <CharacterCard
    character={character}
    index={index}
    isActive={index === activeCardIndex}
    onSelect={onSelectCharacter}
  />
Fix 2: WebGLBackground.jsx — Vector2 Allocation
Creating a new THREE.Vector2 inside useFrame runs at 60fps, generating 60 garbage objects per second. Replace with a pre-allocated ref:
// Add above useFrame:
const mouseVec = useRef(new THREE.Vector2(0.5, 0.5))
// Inside useFrame, reuse instead of allocating:
mouseVec.current.set(
  mouse.current.x / window.innerWidth,
  1.0 - mouse.current.y / window.innerHeight
)
uniforms.uMouse.value.lerp(mouseVec.current, 0.05)
Fix 3: SmoothScroll.jsx — RAF Leak
The requestAnimationFrame loop inside SmoothScroll never gets cancelled. Add a cancel handle to the cleanup:
let rafId
function raf(time) {
  lenis.raf(time)
  rafId = requestAnimationFrame(raf)
}
rafId = requestAnimationFrame(raf)
return () => {
  cancelAnimationFrame(rafId)
  lenis.destroy()
}
4. Performance Improvements
4.1 Video Loading Strategy
Currently all character videos are likely loaded upfront. With 10 MP4 files, this can mean 100–500MB of network requests on page load. Implement intersection-observer-based loading:
Add preload="none" on all video elements by default
Switch to preload="metadata" when card enters viewport (within 1 card distance)
Only call video.load() and video.play() when card becomes active
Pause and unload videos that are more than 2 cards away
Expected impact: 80–90% reduction in initial network payload, faster Time to Interactive.
4.2 Particle Count Reduction
The WeatherSystem and FloatingParticles components generate between 8 and 50 animated elements simultaneously. On mobile or low-power devices this causes frame drops. Recommendations:
Detect device performance using navigator.hardwareConcurrency and window.devicePixelRatio
Scale particle counts: desktop = 100%, tablet = 60%, mobile = 30%
Use CSS will-change: transform only on the active weather layer, not all particles
Replace Framer Motion animate on individual particles with a single canvas-based renderer for the WeatherSystem
Expected impact: +20–40 FPS on mid-range mobile devices.
4.3 WebGL Shader Optimization
The custom GLSL fragment shader in WebGLBackground samples Perlin noise twice per fragment at different frequencies. This is expensive on integrated graphics. Optimizations:
Reduce noise octaves from 2 to 1 on mobile (detect with matchMedia)
Lower the planeGeometry resolution from 64x64 to 32x32 on mobile
Add a uResolution uniform and scale UV coordinates to avoid stretched noise on non-square viewports
Consider replacing the live shader with a pre-rendered video or CSS animation on very low-end devices
4.4 Bundle Size Analysis
Your current dependencies include Three.js, @react-three/fiber, @react-three/drei, and Framer Motion — all of which are large libraries. Recommendations:
Run: npx vite-bundle-analyzer after building to identify the largest chunks
Three.js can be tree-shaken: import only what you use instead of the entire package
@react-three/drei imports many extras — import Stars and PerspectiveCamera directly
Consider dynamic import of WebGLBackground so it does not block the initial render
const WebGLBackground = lazy(() => import('./WebGLBackground'))
5. UX & Design Improvements
5.1 Navigation & Wayfinding
The site has no persistent navigation. Users who want to jump between characters must scroll through the entire HorizontalScroll section or use the CommandPalette (which many users will not discover). Recommendations:
Add a fixed mini-navbar at the top with: site logo, character count indicator, CommandPalette trigger button with keyboard hint
Make the CommandPalette discoverable: show a floating "/" or "Search" button on mobile where keyboard shortcuts do not work
Add character name labels visible below the scroll-progress dots on the right side of HorizontalScroll
Show a "Character X of 10" indicator that updates as users scroll through the deck
5.2 Mobile Experience
Several features degrade significantly on mobile:
The CustomCursor is hidden on mobile (correct), but the cursor.hovering state logic still runs — add a media query check before attaching mousemove listeners
The 3D holographic parallax in CharacterCard uses mouse position, which has no equivalent on touch. Add gyroscope support via DeviceOrientationEvent as a touch parallel
The CommandPalette "/" shortcut does not work on mobile keyboards. Add a visible search icon button
HorizontalScroll requires vertical scroll to move horizontally — add swipe gesture support using touch events
VideoExpander opens full-screen on mobile, but the character image and stats panel stack vertically — test this layout and adjust flex direction breakpoints
5.3 Loading State UX
The 4.8-second Preloader is cinematic but may frustrate returning users. Improvements:
Check sessionStorage on load — if the user has visited before, skip the preloader or reduce it to 1.5 seconds
Add a "Skip intro" button visible after phase 2 (at 0.5 seconds)
Show asset loading progress during the preloader phases rather than just decorative animations
Lazy-load character images during the preloader so they are ready when the deck renders

7.2 Audio System (Detailed)
Your codebase already references an audioManager.playTick() utility in HorizontalScroll.jsx, suggesting audio was planned. Here is the full implementation path:
Create src/utils/audio.js with a singleton AudioContext manager
Use the Web Audio API to create short tick sounds procedurally (no audio files needed for UI sounds)
For character BGM, source royalty-free anime instrumental tracks (Pixabay or Freesound) and name them matching the character IDs: /assets/audio/eren.mp3, etc.
Add an "audio" field to each character object in characters.js
Fade BGM in/out with GainNode when the active character changes — 500ms cross-fade

7.3 Quote System (Detailed)
The characters.js data includes a quote field (/assets/quotes/Eren_qoutes.jpg, etc.) but no component currently renders it. Two approaches:
Approach A — Show as image: Add an image element inside VideoExpander that fades in after the stats animation (at phase 3 + 2 seconds). Position it as a cinematic subtitle overlay at the bottom of the expanded card.
Approach B — Add text quotes to characters.js: Move away from image-based quotes and add a "quote" text string and "quoteSource" string to each character object. Use a typewriter animation (character by character reveal) inside VideoExpander for a much more dynamic effect that also works on all screen sizes.
Approach B is strongly recommended as it avoids layout issues with quote images on mobile and enables text selection, copying, and future features like "Quote of the Day".
8. Code Quality & Architecture
8.1 State Management
Currently, themeColor state is threaded through props from App.jsx down through HorizontalScroll, ShuffleDeck, and WebGLBackground. As the app grows this prop-drilling will become unwieldy. Recommendation:
Create a CharacterContext using React.createContext
Store: activeCharacter, activeIndex, themeColor in the context
WebGLBackground, WeatherSystem, CustomCursor, and ScrollProgress can all read themeColor from context without prop chains
// src/context/CharacterContext.jsx
const CharacterContext = createContext(null)
export const useCharacter = () => useContext(CharacterContext)
8.2 Custom Hooks to Extract
Several components contain logic that could be reusable hooks, making components cleaner and easier to test:
useMediaQuery(query) — already needed in 3+ components for mobile detection
useIntersectionObserver(ref, options) — used in Effects.jsx AnimatedCounter, could simplify several video lazy-load implementations
useThrottledMousePosition() — mouse position is tracked in HeroSection, ShuffleDeck, WebGLBackground, and Effects.jsx separately. Centralizing this saves 4 duplicate event listeners
useCharacterNavigation(characters) — wraps the next/prev/index logic currently duplicated between ShuffleDeck and HorizontalScroll
8.3 TypeScript Migration
The codebase would benefit significantly from TypeScript, especially given the shared character data structure that is consumed by 8+ components:
Add a Character interface in src/types/character.ts with all fields typed
The stats object shape (strength, speed, technique, power, endurance) should be a typed interface
Run: npm install -D typescript @types/react @types/react-dom and add a tsconfig.json to start the migration incrementally
Begin with characters.js and the data layer — the biggest safety win for the lowest effort

11. What Is Already Excellent
Beyond the improvements, it is worth noting what the codebase does exceptionally well:
Custom GLSL shader with Perlin noise and mouse-reactive fluid dynamics — this is expert-level work rarely seen in personal projects
The 5-phase cinematic preloader with kanji rain convergence and particle ring explosion is genuinely impressive
Per-character weather systems (10 different particle types) showing deep creative attention to character identity
The text scramble hook using Japanese katakana characters is a beautiful detail that fits the anime theme perfectly
CommandPalette with fuzzy search and keyboard navigation matches the quality of professional tools like Linear and Raycast
